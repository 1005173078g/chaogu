# A股日报手机网页交付设计

日期：2026-07-23
适用自动化：`a-15-30`（A股收盘复盘与新闻联播日报）

## 1. 背景与目标

当前日报以 HTML 文件通过企业微信机器人 `file` 消息发送。桌面端可以下载后打开，但企业微信手机端通常不能把 HTML 附件直接作为网页预览。现有 HTML 已包含 viewport 与响应式样式，因此问题不在页面排版，而在交付载体。

目标是让用户在企业微信手机端点击一次即可直接阅读完整日报，同时保留：

- 完整中文排版、表格和外部来源链接；
- 每日独立归档链接；
- 一个始终指向最新日报的固定入口；
- 发布失败时不发送失效链接；
- Webhook、访问令牌等秘密不进入仓库、日志或报告。

## 2. 选定方案

使用公开仓库 `1005173078g/chaogu` 的 GitHub Pages 托管日报。

- 最新入口：`https://1005173078g.github.io/chaogu/`
- 日期归档：`https://1005173078g.github.io/chaogu/reports/YYYY-MM-DD.html`
- 发布分支与目录：`main` 分支根目录
- 企业微信交付：发送一条简短的 Markdown 链接通知，不再把 HTML 附件作为常规交付

这里的 Markdown 仅承担“打开网页”的通知功能，不承载或分段复制日报正文，因此不属于报告内容回退。

## 3. 发布架构

日报生成与发布拆为四个边界清晰的阶段：

1. **生成**：在项目 `reports` 目录生成完整 UTF-8 HTML。
2. **验证**：检查日期、0–11 章节、关键来源链接、免责声明、UTF-8 与敏感信息。
3. **发布**：把报告复制到 `github-pages/reports/YYYY-MM-DD.html`，并更新 `github-pages/index.html` 为最新报告内容或同站跳转；提交并推送 `main`。
4. **交付**：轮询日期归档 URL，只有在 HTTP 200 且页面包含当日报告标题时，才向企业微信发送可点击链接。

各阶段只通过明确的文件路径、Git 提交状态和 HTTP 验证结果衔接，避免“本地生成成功”被误判为“手机网页已上线”。

## 4. 页面与手机体验

继续复用现有响应式 HTML，不重新设计桌面视觉。补充以下手机验收标准：

- viewport 宽度正确；
- 320、375、390、414 像素视口下正文无页面级横向溢出；
- 宽表格允许在表格容器内横向滚动，不挤压正文；
- 字号、行距与点击目标适合触屏；
- 外部来源链接可点击；
- 首页与日期归档在手机浏览器中均可直接打开。

## 5. GitHub Pages 启用

优先使用现有 GitHub 凭据，通过 GitHub API 或 `gh` 为仓库启用 Pages，来源设置为 `main / root`。若当前凭据没有仓库管理权限，则停止自动化改造并给出一次性人工操作：

`Settings → Pages → Build and deployment → Deploy from a branch → main / (root) → Save`

启用后必须等待并验证固定入口返回 HTTP 200，不能仅以 API 成功或 Git 推送成功作为上线依据。

## 6. 企业微信消息

成功消息保持短小，示例：

```text
**A股收盘复盘与新闻联播日报｜2026-07-22**
[手机直接打开完整日报](https://1005173078g.github.io/chaogu/reports/2026-07-22.html)
```

消息发送仍使用环境变量 `WECOM_BOT_WEBHOOK`，以 PowerShell `Invoke-RestMethod` 发送 UTF-8 JSON 字节。不得打印 Webhook 完整值。

## 7. 失败与重试

- Git 推送失败：重试一次；仍失败则报告公开可说的错误，不发送网页链接。
- GitHub Pages 尚未部署：在限定时间内轮询；仍非 200 或正文日期不匹配则停止发送。
- 企业微信链接消息失败：重试一次；仍失败则报告错误，不回退 HTML 附件或长 Markdown 正文。
- 旧报告继续保存在项目 `reports` 与 Pages 日期归档中，不覆盖历史归档。
- 不自动删除任何本地或远端历史文件。

## 8. 自动化提示词调整

自动化保留完整 HTML 生成要求，但把常规发送流程改为：

1. 生成并验证 HTML；
2. 发布到 GitHub Pages 日期路径并更新最新入口；
3. 验证线上页面；
4. 企业微信发送手机网页链接。

原“上传 HTML 文件并发送 file 消息”不再作为常规交付，也不作为自动失败回退。只有用户另行明确要求附件时才执行。

## 9. 验收标准

实施完成需同时满足：

1. GitHub Pages 固定入口与当日归档均返回 HTTP 200；
2. 页面正文包含正确日期、标题和完整章节；
3. 手机宽度验证无页面级横向溢出；
4. 企业微信收到一条可点击链接，手机点击后直接打开网页；
5. 自动化配置已改为链接交付，仍保持每天北京时间 22:00；
6. 报告、Git 历史、终端输出及自动化提示词不包含 Webhook 或其他秘密；
7. 发布或验证失败时不发送失效链接。

## 10. 非目标

- 不引入数据库、登录系统或付费托管服务；
- 不重做日报内容结构和视觉品牌；
- 不使用第三方 HTML 预览代理作为长期依赖；
- 不把完整日报正文拆成多条企业微信 Markdown 消息。
